4. EFFICIENCY ANALYSIS:
   - Accuracy-90:  71.82% of dual-path branches needed recovery (useful)
   - Confidence-70: 18.54% of dual-path branches needed recovery (useful)
   - Accuracy-90:   28.2% of dual-path branches were wasted (correctly predicted)
   - Confidence-70:  81.5% of dual-path branches were wasted (correctly predicted)
   - Accuracy mode is MORE efficient (3.87x higher utilization)

   What is "wasted"? Resources consumed for alternate paths never needed:
   ✗ I-cache bandwidth: ~87,051 vs ~7,580 cache line fetches
   ✗ Memory bandwidth: ~5.6MB vs ~485KB (if cache misses)
   ✗ TLB lookups: ~87,051 vs ~7,580 translations
   ✗ APB operations: ~174k vs ~15k operations
   ✓ NOT wasted: Execution resources (alternate paths not executed, just fetched)

====================================================================================================
CONCLUSIONS:
====================================================================================================

1. Accuracy-based switching CAN work with aggressive thresholds (90%)
   - Successfully activates dual-path mode
   - Provides misprediction recovery capability

2. Confidence-based switching is more aggressive:
   - 4.0x more dual-path execution
   - Proactive rather than reactive
   - Catches uncertainty before mispredictions occur

3. Accuracy mode is MORE efficient:
   - 71.82% utilization vs 18.54% for confidence mode
   - Less wasted dual-path execution
   - But may miss some mispredictions due to reactive nature

RECOMMENDATION:
----------------------------------------------------------------------------------------------------
Use accuracy-based switching when:
  - Efficiency is critical (minimize wasted dual-path execution)
  - Workload characteristics are well-known for threshold tuning
  - Can tolerate some missed mispredictions

Use confidence-based switching when:
  - Maximum coverage is important
  - Predictor provides reliable confidence values
  - Prefer proactive over reactive approach
